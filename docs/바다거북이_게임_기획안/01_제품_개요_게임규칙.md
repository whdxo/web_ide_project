# 바다거북이 게임 기획안

## 1) 프로젝트 개요
- **프로젝트명(가칭)**: Turtle Mystery Solo
- **장르**: 수수께끼/추리 기반 싱글 플레이 게임 (바다거북수프 스타일)
- **플랫폼**: 웹(PC/모바일 브라우저)
- **목표**: 플레이어 1명이 AI 진행자(방장)와 상호작용하며 예/아니오 질문으로 사건의 진실을 추리


## 2) 핵심 경험
- 혼자서도 몰입 가능한 추리 퍼즐 경험
- AI 진행자와의 자연스러운 문답 플레이
- 질문 제한/시간 압박 없이 자유롭게 사고를 확장하는 탐구형 플레이
- 정답 도출 시 얻는 반전/학습 경험


## 3) 타깃 유저
- 짧은 세션으로 두뇌 게임을 즐기는 1인 플레이 선호 사용자
- 추리·퍼즐·스토리형 인터랙티브 콘텐츠 선호층
- 출퇴근/자투리 시간에 모바일 웹으로 가볍게 플레이하려는 사용자


## 4) 핵심 게임 규칙 (싱글)
1. 플레이어가 난이도/카테고리를 선택하고 문제를 시작한다.
2. **AI 방장(진행자)**이 문제를 제시하고 플레이어 질문에 **예/아니오/상관없음**으로 응답한다.
3. 플레이어는 **제한시간/제한 질문 수 없이** 자유롭게 질문할 수 있다.
4. 플레이어는 정답을 **맞출 때까지 여러 번 제출**할 수 있다.
5. 플레이어가 정답을 맞춘 경우에만 결과 및 해설을 제공한다.
6. 플레이어가 정답을 끝내 맞추지 못하고 이탈/종료하면 결과/해설은 제공하지 않는다.

### 규칙 보강(운영 안정화용)
- 문제당 힌트는 **정확히 3회** 사용 가능
- 질문 로그/핵심 키워드 자동 하이라이트 제공
- 무의미 반복 질문 방지용 AI 가이드 응답(예: “이미 확인된 정보입니다”)


## 5) 게임 모드 제안
### A. 클래식 모드 (MVP 우선)
- 1문제 단위 진행
- 무제한 질문/무제한 정답 시도
- 힌트 3회

### B. 데일리 모드 (2차 확장)
- 매일 1개 고정 문제
- 정답 성공 사용자 기준 평균 질문 수/평균 힌트 사용량 비교 지표 제공


## 6) 콘텐츠 설계
- **난이도**: 쉬움/보통/어려움
- **카테고리**: 일상, 범죄, 공포, 판타지, 블랙코미디
- **메타데이터**:
  - 제목
  - 문제 본문
  - 정답(핵심 진실)
  - 해설(스토리 전체)
  - 허용 키워드/의미 벡터(정답 유사 판정용)
  - 힌트 단계(1차/2차/3차)
  - 금지/주의 표현 태그

### 콘텐츠 수급 전략
- 초기: 내부 제작 문제 100개 확보
- 이후: 유저 문제 제보 + 운영자 검수 후 반영
- 시즌 테마팩(할로윈, 여름특집 등) 정기 업데이트


## 7) 점수/보상 시스템 (싱글)
- 기본 점수: 정답 시 +100
- 질문 효율 보너스: 적은 질문으로 정답 시 +0~30
- 힌트 사용 패널티: -10~-30
- 오답 제출 페널티 없음(학습/탐구형 플레이 유도)


## 8) UX/UI 구조
### 메인 화면
- 빠른 시작
- 난이도/카테고리 선택
- 모드 선택(클래식/데일리)

### 게임 화면
- 상단: 문제 텍스트, 사용 힌트 수(0/3)
- 중앙: 질문/AI 응답 로그(채팅형)
- 하단: 질문 입력, 정답 제출, 힌트 버튼
- 보조 패널: 누적 정답 시도 횟수, 핵심 단서 노트

### 결과 화면
- **정답 성공 시에만 진입 가능**
- 정답/해설 공개
- 플레이 분석(질문 수, 정답 시도 횟수, 힌트 사용량)
- 재도전/다음 문제 CTA


## 9) 기술 기획 (웹 기준, 별도 백엔드 분리 없이)
- **프레임워크**: Next.js 단일 애플리케이션 (App Router)
- **구성 방식**: 별도 백엔드 서비스를 분리하지 않고 Next.js 내 서버 기능(Route Handler/Server Action) 활용
- **데이터 저장**:
  - 문제/세션/로그는 별도 DB(예: PostgreSQL)에서 중앙 관리
  - 정적 에셋(설명 이미지 등)은 오브젝트 스토리지 사용 가능
- **AI 방장 구성**:
  - Next.js 서버 액션 또는 Route Handler를 통한 AI 호출 오케스트레이션
  - 응답 제어(예/아니오/상관없음 규칙 강제)
  - 정답 유사도 판정(키워드 + 임베딩)
- **운영**: Vercel 배포, 기본 로그/에러 모니터링, 프롬프트 버전 관리

### 주요 도메인 모델
- UserProfile (익명 계정 기반)
- Puzzle
- PlaySession
- QuestionLog
- HintUsage
- AttemptResult
- DailyChallengeRecord


## 10) MVP 범위 (1차 출시)
### 포함
- 비회원 닉네임 기반 플레이(세션/기록은 DB 저장)
- 클래식 모드
- AI 방장 문답(예/아니오/상관없음)
- 문제 DB 100개
- 문제당 힌트 3회
- 무제한 질문/무제한 정답 시도
- 정답 성공 시 결과/해설 공개

### 제외(후순위)
- 멀티플레이/실시간 방 시스템
- 챌린지 모드
- 시즌 랭킹 글로벌 경쟁전
- 사용자 제작 문제 실시간 반영
- 음성 입력/음성 합성


## 11) 개발 일정(예시: 6주)
- **1주차**: 싱글 UX 플로우 확정, 문제 데이터 스키마/프롬프트 정책 정의
- **2주차**: 문제 플레이 루프(Next UI + 상태관리) 구현
- **3주차**: AI 응답 제어/정답 판정 로직 구현
- **4주차**: 힌트/결과 화면/DB 기록 연동 구현
- **5주차**: 콘텐츠 투입, 난이도/판정 튜닝, QA
- **6주차**: 오픈 베타, 지표 수집, 핫픽스


## 12) 운영 지표(KPI)
- D1/D7 리텐션
- 평균 세션 길이
- 문제당 평균 질문 수
- 문제당 평균 정답 시도 횟수
- 힌트 사용률(난이도 밸런스 핵심)
- 정답 도달률(중도 이탈 대비)


## 13) 리스크 및 대응
- **AI 오답/비일관 응답**: 규칙 기반 가드레일 + 골든셋 회귀 테스트
- **정답 판정 논란**: 키워드 사전 + 임베딩 임계치 + 판정 로그 점검
- **콘텐츠 소진**: 데일리/시즌 문제 순환 + 제보 시스템
- **비용 이슈(AI 호출)**: 캐시, 소형 모델 우선, 고비용 경로 제한

## 14-1) 비기능 요구사항 (시니어 피드백 반영)
- 성능: 주요 API(`start/ask/hint/attempt`)의 p95 응답시간 2초 이내 목표
- 안정성: 베타 기간 서비스 가용성 99.5% 이상
- 보안: 세션 토큰 암호화 저장, 민감 로그 마스킹 원칙 적용
- 운영성: 장애 발생 시 30분 내 1차 원인 분류 및 공지
- 확장성: 문제 데이터 100개 → 1,000개 확장 시에도 조회 성능 유지

## 14-2) 범위 통제 원칙 (시니어 피드백 반영)
- MVP 기간에는 신규 모드 추가 금지(클래식 중심 고정)
- 점수 규칙 변경은 주간 1회 배치 반영만 허용
- 임계치/정책 변경은 QA 재승인 없이는 배포 금지
