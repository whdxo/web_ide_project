# 바다거북이 게임 기획안

## 15) AI 방장 프롬프트 초안

### 15-1. 시스템 역할 정의
- 당신은 바다거북이 게임의 **AI 방장**이다.
- 목표는 플레이어가 사건의 진실을 스스로 추리하도록 돕는 것이며, 정답을 직접 누설하면 안 된다.
- 모든 질문 응답은 기본적으로 아래 3가지 중 하나를 우선한다.
  - `예`
  - `아니오`
  - `상관없음`

### 15-2. 입력 컨텍스트
- puzzle.title
- puzzle.question
- puzzle.answer (정답 원문)
- puzzle.explanation (해설 원문)
- puzzle.allowed_keywords (핵심 키워드 목록)
- session.question_history
- session.hint_used_count (0~3)
- user.latest_message (질문 또는 정답 시도)
- mode (`question` | `answer_attempt` | `hint_request`)

### 15-3. 응답 정책
- `question` 모드:
  1. 먼저 사건 핵심 인과와 관련 있는지 판별
  2. `예/아니오/상관없음` 중 1개 선택
  3. 플레이어에게는 `예/아니오/상관없음`만 반환하고 추가 설명은 제공하지 않는다.
  4. 내부 품질 확인용으로 `decision_reason`을 운영 로그에만 저장한다(플레이어 비노출).
- `answer_attempt` 모드:
  - 채점 엔진 결과만 사용하여 `정답`, `오답` 반환
  - 오답 시 해설/핵심 단서 공개 금지
- `hint_request` 모드:
  - 남은 힌트가 있을 때만 단계별 힌트 제공
  - 3회 초과 요청 시 `힌트를 모두 사용했습니다.` 고정 응답

### 15-4. 금지 규칙
- 정답 문장을 그대로 또는 유사하게 재진술 금지
- 질문받지 않은 정보 선제 공개 금지
- 모호한 질문에 장문 추론 제공 금지
- 공격적/혐오 표현 금지

### 15-5. 출력 포맷(JSON)
```json
{
  "type": "question_response | attempt_result | hint_response",
  "decision": "예 | 아니오 | 상관없음 | 정답 | 오답",
  "message": "사용자에게 보여줄 짧은 문장",
  "safety": {
    "spoiler_risk": "low | medium | high",
    "policy_violation": false
  }
}
```

## 16) 정답 판정 로직 명세 (임계치 포함)

### 16-1. 판정 파이프라인
1. **정규화**: 소문자화, 특수문자 제거, 조사/불용어 정리
2. **키워드 매칭 점수** 산출
3. **의미 유사도 점수**(임베딩 cosine similarity) 산출
4. 가중합으로 최종 점수 계산
5. 임계치 기반으로 정답/오답 결정

### 16-2. 점수 계산식(초안)
- `keyword_score`: 0.0 ~ 1.0
  - 허용 키워드 일치율 + 핵심 키워드 가중치 반영
- `semantic_score`: 0.0 ~ 1.0
  - 정답 원문 vs 사용자 시도 문장 임베딩 유사도
- `final_score = 0.6 * keyword_score + 0.4 * semantic_score`

### 16-3. 임계치 정책
- `final_score >= 0.78` → **정답**
- `0.70 <= final_score < 0.78` → **재확인 구간**
  - 재확인 질문 1회 유도: `조금 더 구체적으로 원인을 설명해보세요.`
- `< 0.70` → **오답**

### 16-4. 예외 규칙
- 정답 핵심 엔티티(인물/행동/원인) 중 필수 2개 미포함 시 상한 캡 적용
  - 예: 필수 엔티티 2개 미포함이면 최대 `0.69`
- 금지 키워드 포함(무관 추측/욕설) 시 즉시 오답
- 동일 오답 반복 3회 이상이면 가벼운 방향성 힌트 추천(힌트 사용과 별개)

### 16-5. 판정 로그 스키마
- `attempt_text`
- `keyword_score`
- `semantic_score`
- `final_score`
- `decision`
- `required_entities_hit`
- `timestamp`

## 17) MVP 백로그 (우선순위/스토리포인트)

> 기준: Fibonacci (1,2,3,5,8)

### Epic A. 코어 플레이 루프
1. 문제 시작 화면(난이도/카테고리 선택) — **3pt**
2. 문제 본문 노출 + 질문 입력 UI — **5pt**
3. AI 예/아니오/상관없음 응답 연결 — **8pt**
4. 질문 로그 누적 및 스크롤 복원 — **3pt**
5. 정답 시도 입력/제출 — **3pt**

### Epic B. 판정/힌트 시스템
1. 정답 판정 파이프라인 구현(키워드+유사도) — **8pt**
2. 재확인 구간 UX 처리(0.70~0.78) — **3pt**
3. 힌트 3회 제한 로직 — **3pt**
4. 오답 시 해설 비공개 정책 적용 — **2pt**
5. 정답 성공 시 결과/해설 화면 노출 — **3pt**

### Epic C. 상태 저장/운영
1. PlaySession DB 저장(PostgreSQL) — **5pt**
2. 재접속/새로고침 복구(현재 문제/로그/힌트 사용량, DB 기반) — **5pt**
3. 에러 상태 UX(응답 지연/실패 재시도) — **3pt**
4. 기본 이벤트 로깅(시도횟수/질문수/정답도달) — **3pt**

### Epic D. 데일리 모드 (MVP+)
1. 일일 문제 로딩 규칙(클라이언트 기준 날짜) — **3pt**
2. 데일리 결과 저장 및 재도전 제한 정책 — **5pt**
3. 개인 비교 지표(평균 질문 수/힌트 사용량) — **3pt**

### 마일스톤 제안
- **M1 (2주)**: Epic A 완료
- **M2 (4주)**: Epic B, C 완료 (클래식 모드 출시 가능)
- **M3 (6주)**: Epic D + 안정화

## 17-1) AI 정책 버전관리 및 회귀 검증 (시니어 피드백 반영)

### A. 정책 버전관리
- 프롬프트/판정 파라미터는 `policy_version`으로 관리한다.
- 운영 로그에는 `policy_version`, `model_version`을 함께 기록한다.
- 정책 변경 시 변경 사유/영향 범위/롤백 방법을 릴리즈 노트에 필수 기재한다.

### B. 회귀 검증 셋
- 골든셋: 최소 20문제 × 문제당 대표 질문 15개 이상
- 평가 항목
  - `예/아니오/상관없음` 정확도
  - 스포일러 누출률
  - 경계값(0.70/0.78) 판정 일관성
- 배포 조건: 직전 버전 대비 핵심 지표 악화가 없어야 한다.

### C. 실패 대응
- 누출/오판 급증 시 직전 `policy_version`으로 즉시 롤백
- 롤백 후 24시간 내 사후 분석 리포트 작성
