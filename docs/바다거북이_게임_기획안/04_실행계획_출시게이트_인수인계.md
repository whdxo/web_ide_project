# 바다거북이 게임 기획안

## 23) 1주차 작업 티켓(이슈) 분해안

### 23-1. Epic: 프로젝트 부트스트랩

#### TM-001 Next.js App Router 기본 골격 생성
- 목적: 페이지/레이아웃/공통 스타일 구조를 초기화한다.
- 완료 조건(DoD)
  - `/`, `/play/[puzzleId]`, `/result/[sessionId]`, `/daily` 라우트 skeleton 생성
  - 공통 레이아웃 및 에러/로딩 경계 추가
  - 기본 lint/build 통과
- 예상: **2pt**

#### TM-002 환경변수 및 실행 프로필 정리
- 목적: 로컬/스테이징 실행 설정을 표준화한다.
- 완료 조건(DoD)
  - `.env.example`에 DB/AI 키/앱 URL 키 정의
  - 런타임에서 필수 env 누락 시 명시적 에러 처리
- 예상: **1pt**

### 23-2. Epic: DB 및 마이그레이션

#### TM-010 PostgreSQL 연결 계층 구성
- 목적: 앱에서 DB 풀을 일관되게 사용하도록 한다.
- 완료 조건(DoD)
  - DB 커넥션 유틸 추가
  - 연결 실패 시 재시도/로그 정책 반영
- 예상: **2pt**

#### TM-011 초기 스키마 마이그레이션 작성
- 목적: `sessions/question_logs/attempt_logs/puzzles` 테이블 생성.
- 완료 조건(DoD)
  - 스키마 적용/롤백 스크립트 존재
  - 로컬 DB에서 마이그레이션 up/down 검증 완료
- 예상: **3pt**

#### TM-012 인덱스 및 제약조건 추가
- 목적: 조회 성능과 데이터 정합성 확보.
- 완료 조건(DoD)
  - `sessions(status, started_at)`, `question_logs(session_id, created_at)` 인덱스
  - FK/NOT NULL/UNIQUE 제약 반영
- 예상: **2pt**

### 23-3. Epic: API 최소 동작 구현

#### TM-020 POST /api/session/start
- 목적: 플레이 시작 시 세션 생성 및 문제 할당.
- 완료 조건(DoD)
  - Request 검증(닉네임/모드/난이도/카테고리)
  - Response 스펙(문서 20-3) 일치
  - `sessions` row 생성 확인
- 예상: **3pt**

#### TM-021 POST /api/session/{id}/ask
- 목적: 질문 입력에 대해 `예/아니오/상관없음` 반환.
- 완료 조건(DoD)
  - decision 이외 부가 설명 비노출
  - `decision_reason` 내부 로그 저장
  - `question_logs` 적재 확인
- 예상: **5pt**

#### TM-022 POST /api/session/{id}/hint
- 목적: 힌트 3회 제한 정책 적용.
- 완료 조건(DoD)
  - 1~3회 정상 응답
  - 4회차 `HINT_LIMIT_EXCEEDED` 반환
  - `sessions.hint_used_count` 정확 증가
- 예상: **3pt**

### 23-4. Epic: QA/운영 준비(1주차 범위)

#### TM-030 API 스모크 테스트 스크립트
- 목적: 핵심 3개 API의 정상/예외 흐름 빠른 검증.
- 완료 조건(DoD)
  - start → ask → hint(4회) 시나리오 자동 실행
  - 실패 시 원인 출력(상태코드/본문)
- 예상: **2pt**

#### TM-031 공통 로깅 필드 강제
- 목적: 운영 추적성을 위한 최소 로그 포맷 보장.
- 완료 조건(DoD)
  - `sessionId`, `route`, `latency`, `errorCode` 로그 포함
  - 샘플 로그 문서화
- 예상: **2pt**

### 23-5. 1주차 스프린트 목표
- 총 예상: **25pt 내외**
- 목표 결과물
  1. Next.js 기본 골격 + DB 마이그레이션 완료
  2. `start/ask/hint` API 동작 및 정책 반영
  3. 스모크 테스트 + 공통 로그 포맷 적용

### 23-6. 리스크/의존성
- AI API 키 발급 지연 시 `ask` 엔드포인트는 mock decision 모드로 대체
- DB 접근 지연 시 로컬 docker postgres 프로파일 우선 사용
- 문서/구현 스펙 불일치 방지를 위해 API 응답 스냅샷 테스트를 1주차 내 도입 권장


## 24) 기획 확정본 (Final)

### 24-1. 최종 확정 규칙 요약
- 플레이 방식: **싱글 플레이 전용**
- 진행자: **AI 방장**
- 질문 제한: **없음**
- 정답 시도 제한: **없음**(정답 도달 시까지 반복 가능)
- 힌트: **문제당 3회**
- 결과/해설 공개 조건: **정답 성공 세션에 한해 공개**
- 중도 종료(`giveup|leave`) 또는 미해결 세션: **결과/해설 비공개**

### 24-2. 기술 확정안
- 애플리케이션: Next.js(App Router)
- 아키텍처: 별도 백엔드 서비스 분리 없이 Next.js 서버 기능 활용
- 데이터 저장: PostgreSQL 중앙 관리
- 핵심 API: `start / ask / hint / attempt / result`
- 운영 로그: `decision_reason` 포함(플레이어 비노출)

### 24-3. MVP 포함/제외 최종본
- 포함
  - 클래식 모드
  - 데일리 모드(확장 우선순위 높음)
  - 문제 100개, 힌트 3단계, 정답 판정 파이프라인
- 제외
  - 멀티플레이
  - 음성 입출력
  - 글로벌 경쟁 랭킹

## 27) 시니어 피드백 라운드 기록 (3회)

### Round 1
- 피드백: "문서는 상세하지만 운영 기준과 비기능 요구사항이 부족함. MVP에서 무엇을 절대 고정할지 명확히 하라."
- 반영:
  - 01 문서에 비기능 요구사항(성능/안정성/보안/운영/확장성) 추가
  - MVP 범위 통제 원칙(모드/점수/임계치 변경 제한) 추가

### Round 2
- 피드백: "AI 정책이 바뀌면 품질 흔들림이 크다. 버전관리와 회귀 검증 프로세스를 명문화하라."
- 반영:
  - 02 문서에 `policy_version`/`model_version` 로깅 기준 추가
  - 골든셋 기반 회귀 검증 및 롤백 절차 추가

### Round 3
- 피드백: "API/데이터 거버넌스가 약함. 버저닝, 멱등성, 로그 보존/삭제 정책을 명시해야 실서비스 가능하다."
- 반영:
  - 03 문서에 API 버저닝(`/api/v1`), Idempotency-Key, x-request-id 기준 추가
  - 로그 보존기간(90일), 삭제정책(24시간), 감사필드 권장사항 추가

### 최종 결론
- 시니어 리뷰 3회 반영 후, 본 기획안은 **MVP 구현 착수 + 베타 운영 준비 가능한 수준**으로 승인.
